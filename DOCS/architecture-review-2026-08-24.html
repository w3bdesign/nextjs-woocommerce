Problem: the Cart has no module — fetch, format, sync, and the "wait 2–3s for WooCommerce to settle" retry hack are copy-pasted across four components.

Solution: one useCart() interface; query, mutation, formatting, settle-refetch, and store sync become implementation.

  • locality: cart bugs concentrate in one module
  • leverage: one interface, four call sites
  • tests hit one interface
  • settle-hack fixed once, everywhere
  • delete 4 copies of the ritual

Problem: session persistence leaks across the seam — woo-session:v1 / woocommerce-cart:v1 are duplicated constants with three independent writers.

Solution: one wooSession module owns keys, expiry (7 days), and clearing; localStorage becomes an adapter behind the seam.

  • two adapters justify the seam: localStorage in prod, in-memory in tests
  • Apollo middleware becomes testable
  • key drift becomes impossible
  • expiry logic lives in one place

Problem: handleQuantityChange was extracted for testability, but the bugs live in the mutation/refetch dance around it — no locality; the rest is five concerns sharing a filename.

Solution: each function moves into the module whose implementation it belongs to; the re-export shim is deleted.

  • locality: cart shaping tested inside the Cart module
  • delete the backward-compat shim
  • deletion test passes: file vanishes, nothing orphaned

Problem: login() constructs a second ApolloClient that bypasses the shared client's session middleware — the woocommerce-session header never rides along with login.

Solution: login uses the shared client; if isolation was intentional, that reason belongs in an ADR, not in an unexplained second client.

  • one seam to WPGraphQL, not two
  • session behaviour uniform across all requests
Speculative: the second client may be deliberate (avoid attaching a guest session to login). If so, record the reason as an ADR.

Top recommendation

Deepen the Cart into one module

It has the most leverage — one interface replaces four copies of the fetch→format→sync→settle ritual — and it pulls candidates 3 and 4 in behind it for free: the store interface shrinks and the grab-bag dissolves as side effects of the same deepening.
